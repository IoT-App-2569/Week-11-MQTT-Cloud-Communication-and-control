1. เพราะเหตุใดเราจึงต้องส่งข้อความสถานะ `iot/node01/status = "online"` ด้วยแฟล็ก `retain = 1` ควบคู่กับการตั้งค่า Last Will and Testament (LWT) ว่า `"offline"`

```text
**เพื่อให้ Topic `iot/node01/status` เก็บสถานะล่าสุดที่ถูกต้องของอุปกรณ์ไว้ที่ Broker ตลอดเวลา**
 
- ทั้งข้อความ `online` และ LWT `offline` ถูกส่งด้วย `retain = 1` ทั้งคู่ จึงเขียนทับกันที่ Topic เดียวกัน ทำให้ Broker เก็บไว้เพียงสถานะล่าสุดเสมอ
- เมื่อบอร์ดหลุดการเชื่อมต่ออย่างผิดปกติ Broker จะเผยแพร่ LWT `offline` และเก็บค่านี้แทน `online` ทำให้ Client ที่เข้ามาภายหลังทราบทันทีว่าอุปกรณ์ออฟไลน์
- เมื่อบอร์ดเชื่อมต่อกลับมาได้ใน `MQTT_EVENT_CONNECTED` จะส่ง `online` แบบ Retain ทับค่า `offline` เดิม หากไม่ใช้ Retain ค่า `offline` ที่ค้างอยู่จะทำให้แอปพลิเคชันเข้าใจผิดว่าอุปกรณ์ยังออฟไลน์
- แดชบอร์ดหรือแอปพลิเคชันที่เพิ่งเปิดขึ้นมาไม่ต้องรอ Telemetry รอบถัดไป ก็สามารถแสดงสถานะออนไลน์หรือออฟไลน์ได้ทันทีที่ Subscribe```

2. หากเครือข่าย Wi-Fi หลุดชั่วคราว คอมโพเนนต์ `esp-mqtt` มีพฤติกรรมการจัดการอย่างไร และเมื่อสัญญาณกลับมา โค้ดจำเป็นต้องเรียกฟังก์ชันเชื่อมต่อใหม่ด้วยตนเองหรือไม่

```text
**ไม่จำเป็นต้องเรียกฟังก์ชันเชื่อมต่อ MQTT ใหม่เอง เพราะ `esp-mqtt` มีระบบ Auto Reconnect ในตัว**
 
- เมื่อการเชื่อมต่อ TCP ขาด `esp-mqtt` จะส่งเหตุการณ์ `MQTT_EVENT_DISCONNECTED` แล้วพยายามเชื่อมต่อ Broker ใหม่อัตโนมัติเป็นระยะ (ค่าเริ่มต้นประมาณทุก 10 วินาที ปรับได้ด้วย `reconnect_timeout_ms`) จนกว่าจะสำเร็จ
- ส่วนการเชื่อมต่อ Wi-Fi ใหม่ โค้ดจัดการไว้แล้วใน `wifi_event_handler` โดยเรียก `esp_wifi_connect()` เมื่อเกิด `WIFI_EVENT_STA_DISCONNECTED`
- เมื่อเชื่อมต่อ Broker สำเร็จ จะเกิด `MQTT_EVENT_CONNECTED` อีกครั้ง โค้ดจึงส่ง `online` และ Subscribe `iot/node01/cmd/led` ใหม่โดยอัตโนมัติ ซึ่งจำเป็น เพราะค่าเริ่มต้นเป็น Clean Session ทำให้ Broker ไม่จำการ Subscribe เดิมไว้
- ข้อความ Telemetry ที่ส่งด้วย QoS 0 ระหว่างที่หลุดจะสูญหายไป ส่วนข้อความ QoS 1 ขึ้นไปจะถูกเก็บไว้ใน Outbox และส่งซ้ำเมื่อเชื่อมต่อกลับมา```

3. ในฟังก์ชัน `telemetry_task` เพราะเหตุใดหลังจากเรียก `cJSON_PrintUnformatted(root)` แล้วเราจึงจำเป็นต้องเรียกฟังก์ชัน `free(json_str)` และ `cJSON_Delete(root)` เสมอ? หากละเลยจะมีผลเสียอย่างไรต่อหน่วยความจำของ ESP32

```text
**เพราะ cJSON จองหน่วยความจำแบบ Dynamic บน Heap และภาษา C ไม่มี Garbage Collector คืนหน่วยความจำให้อัตโนมัติ**
 
- `cJSON_CreateObject()` และ `cJSON_Add...ToObject()` จองหน่วยความจำ (`malloc`) สำหรับแต่ละโหนดของโครงสร้าง JSON ต้องคืนทั้งหมดด้วย `cJSON_Delete(root)`
- `cJSON_PrintUnformatted(root)` จองหน่วยความจำก้อนใหม่แยกต่างหากเพื่อเก็บข้อความ JSON ต้องคืนด้วย `free(json_str)` เพราะ `cJSON_Delete()` ไม่ได้คืนส่วนนี้ให้
- หากละเลย จะเกิด Memory Leak สะสมทุกรอบที่ส่ง Telemetry (ทุก 4 วินาที) Heap ที่เหลือจะลดลงเรื่อยๆ และเกิด Heap Fragmentation
- เมื่อ Heap หมด `malloc` จะคืนค่า `NULL` ทำให้สร้าง JSON ไม่ได้ ส่งข้อมูลไม่ได้ ระบบ Wi-Fi และ MQTT ที่ต้องใช้ Heap เช่นกันจะทำงานผิดปกติ จนบอร์ดค้างหรือรีบูตตัวเอง```
