# ใบงานการทดลองที่ 11.1

## 5. คำถามท้ายการทดลอง (Post-Lab Questions)
1. เพราะเหตุใดสัญลักษณ์ `#` จึงต้องวางไว้ที่ตำแหน่งท้ายสุดของ Topic เสมอ? หากกำหนด Topic Filter เป็น `home/#/light` จะเกิดข้อผิดพลาดอย่างไร?
```text
**`#` ต้องอยู่ท้ายสุดเพราะแทนทุกระดับชั้นที่เหลือทั้งหมด และ `home/#/light` เป็น Invalid Topic Filter**
 
- `#` เป็น Multi-level Wildcard ที่ครอบคลุมทุกระดับชั้นตั้งแต่ตำแหน่งที่วางไปจนสุด Topic
- หากมีระดับชั้นอื่นตามหลัง Broker จะไม่สามารถระบุได้ว่า `#` ควรครอบคลุมกี่ระดับ มาตรฐาน MQTT
จึงกำหนดให้ `#` เป็นอักขระสุดท้ายและอยู่ในระดับชั้นของตัวเองเท่านั้น
- เมื่อใช้ `home/#/light` โปรแกรม `mosquitto_sub` จะแจ้ง Error และไม่ส่งแพ็กเก็ต `SUBSCRIBE` ออกไป
- หาก Client อื่นส่งไปถึง Broker จะถูกตัดการเชื่อมต่อ (MQTT 3.1.1) หรือได้รับ `SUBACK` พร้อม Reason Code `0x8F` (MQTT 5)
```
2. ในระบบงานติดตามยานพาหนะ (GPS Tracking) ที่ส่งพิกัดรถยนต์ทุกๆ 1 วินาที ท่านคิดว่าควรเลือกระดับ QoS ใดระหว่าง QoS 0, 1 หรือ 2 เพราะเหตุใด?
```text
**ควรเลือก QoS 0 (At Most Once) เพราะข้อมูลมาใหม่ตลอดเวลาและต้องการ Overhead ต่ำ**
 
- พิกัดใหม่ถูกส่งมาทุก 1 วินาที หากจุดใดสูญหาย จุดถัดไปจะมาแทนที่ทันที ข้อมูลแต่ละจุดจึงหมดคุณค่าอย่างรวดเร็ว
- QoS 0 ใช้เพียงแพ็กเก็ต `PUBLISH` เดียว ส่วน QoS 1 ต้องเพิ่ม `PUBACK` และ QoS 2 ต้องเพิ่ม `PUBREC`, `PUBREL`, `PUBCOMP`
- จำนวนแพ็กเก็ตที่มากขึ้นทำให้สิ้นเปลืองแบนด์วิดท์เครือข่ายมือถือและพลังงานของอุปกรณ์
- การส่งซ้ำ (Retransmission) ของ QoS 1 และ 2 ขณะสัญญาณไม่ดี อาจทำให้พิกัดเก่ามาถึงหลังพิกัดใหม่
```
3. หาก Client ส่งแพ็กเก็ต `DISCONNECT` ไปยัง Broker อย่างถูกต้องก่อนปิดโปรแกรม ข้อความ Last Will and Testament (LWT) จะถูกเผยแพร่ออกไปหรือไม่ เพราะเหตุใด?
```text
**LWT จะไม่ถูกเผยแพร่ เพราะเป็นการตัดการเชื่อมต่ออย่างถูกต้อง (Graceful Disconnection)**
 
- LWT ทำงานเฉพาะเมื่อ Client หลุดการเชื่อมต่ออย่างผิดปกติ (Ungraceful Disconnection)
เช่น ไฟดับ เครือข่ายขาด หรือ Keep Alive หมดเวลา
- เมื่อ Broker ได้รับ `DISCONNECT` ที่ถูกต้อง มาตรฐาน MQTT กำหนดให้ลบ Will Message ทิ้งทันที
- Broker ถือว่า Client ตั้งใจออกจากระบบเอง จึงไม่จำเป็นต้องแจ้งเตือน Subscriber
- ในการทดลอง การกด `Ctrl+C` จะส่ง `DISCONNECT` ตามปกติ จึงไม่เห็นข้อความ LWT
```
4. Retained Message มีประโยชน์อย่างไรในการออกแบบระบบแดชบอร์ด Smart Home สำหรับผู้ใช้งานที่เพิ่งเปิดแอปพลิเคชันขึ้นมาเป็นครั้งแรก?
```text
**Retained Message ทำให้แดชบอร์ดแสดงสถานะปัจจุบันได้ทันทีที่เปิดแอปพลิเคชัน**
 
- Broker เก็บข้อความล่าสุดของแต่ละ Topic ไว้ และส่งให้ทันทีเมื่อแอปพลิเคชัน Subscribe เช่น `home/#`
- ผู้ใช้เห็นสถานะปัจจุบัน เช่น ไฟเปิดอยู่ หรืออุณหภูมิ 26.4 °C โดยไม่ต้องรอข้อมูลรอบใหม่
- อุปกรณ์แบบ Event-driven เช่น สวิตช์ไฟหรือเซนเซอร์ประตู ส่งข้อมูลเฉพาะเมื่อสถานะเปลี่ยน
หากไม่มี Retained Message แดชบอร์ดจะว่างเปล่าจนกว่าจะมีการเปลี่ยนแปลง
- อุปกรณ์ไม่ต้องส่งสถานะซ้ำเป็นระยะ หรือสร้างกลไกถาม-ตอบสถานะแยกต่างหาก
```
