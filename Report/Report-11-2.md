## คำถามท้ายการทดลอง (Post-Lab Questions)

**1. เพราะเหตุใดเราจึงต้องส่งข้อความสถานะ `iot/node01/status = "online"` ด้วยแฟล็ก `retain = 1` ควบคู่กับการตั้งค่า Last Will and Testament (LWT) ว่า `"offline"`?**
**ตอบ:** การส่งสถานะ "online" พร้อมแฟล็ก retain = 1 จะทำให้ MQTT Broker จดจำข้อความนี้ไว้เป็นค่าล่าสุด เมื่อมีแอปพลิเคชันหรือแดชบอร์ดเข้ามา Subscribe หัวข้อนี้ในภายหลัง จะได้รับสถานะ "online" ทันทีโดยไม่ต้องรอให้อุปกรณ์ส่งข้อความมาใหม่ และเมื่อนำมาใช้คู่กับ LWT ที่ตั้งค่าเป็น "offline" หากบอร์ด ESP32 ขาดการเชื่อมต่อกะทันหัน Broker จะนำข้อความ LWT ส่งแจ้งเตือนไปยัง Subscriber ทันที ทำให้ระบบโดยรวมสามารถรู้สถานะปัจจุบัน ของอุปกรณ์ได้อย่างถูกต้อง

**2. หากเครือข่าย Wi-Fi หลุดชั่วคราว คอมโพเนนต์ `esp-mqtt` มีพฤติกรรมการจัดการอย่างไร และเมื่อสัญญาณกลับมา โค้ดจำเป็นต้องเรียกฟังก์ชันเชื่อมต่อใหม่ด้วยตนเองหรือไม่?**
**ตอบ:** คอมโพเนนต์ esp-mqtt ในเฟรมเวิร์ก ESP-IDF มีระบบ Auto-reconnect ฝังมาให้ในตัว เมื่อสัญญาณ Wi-Fi หลุด ฟังก์ชัน wifi_event_handler ในโค้ดจะพยายามเชื่อมต่อ Wi-Fi ใหม่ และเมื่อ Wi-Fi สามารถเชื่อมต่อและได้รับ IP Address กลับมาแล้ว ตัว esp-mqtt จะทำการเชื่อมต่อกับ MQTT Broker ให้ใหม่โดยอัตโนมัติ โค้ดในโปรแกรมหลักจึง ไม่จำเป็น ต้องเรียกฟังก์ชันเพื่อเริ่มต้นการเชื่อมต่อ MQTT ใหม่อีกครั้ง

**3. ในฟังก์ชัน `telemetry_task` เพราะเหตุใดหลังจากเรียก `cJSON_PrintUnformatted(root)` แล้วเราจึงจำเป็นต้องเรียกฟังก์ชัน `free(json_str)` และ `cJSON_Delete(root)` เสมอ? หากละเลยจะมีผลเสียอย่างไรต่อหน่วยความจำของ ESP32?**
**ตอบ:** เพราะไลบรารี cJSON จะใช้การจองพื้นที่หน่วยความจำแบบไดนามิก ไว้บน Heap สำหรับเก็บโครงสร้าง JSON Object และข้อความ String จึงจำเป็นต้องคืนพื้นที่หน่วยความจำเหล่านั้นกลับสู่ระบบทุกครั้งเมื่อใช้งานเสร็จ
