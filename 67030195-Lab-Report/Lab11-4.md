## 5. คำถามท้ายการทดลอง (Post-Lab Questions)
1. ในสถาปัตยกรรม ESP RainMaker กระบวนการ **Assisted Claiming** ช่วยแก้ปัญหาเรื่องการติดตั้งใบรับรองความปลอดภัย (Security Certificates) บนอุปกรณ์ในขั้นตอนพัฒนาต้นแบบได้อย่างไร?

   **ตอบ** ช่วยลดภาระการแฟลช Certificate แบบแมนนวล โดยให้อุปกรณ์เจรจาขอคีย์ความปลอดภัยจากคลาวด์ผ่านสมาร์ทโฟนได้โดยตรง ทำให้พร้อมเชื่อมต่อผ่าน mTLS ได้ทันที
   
2. เพราะเหตุใดฟังก์ชัน `write_cb` จึงต้องเรียกคำสั่ง `esp_rmaker_param_update_and_report()` ทุกครั้งที่มีการเปลี่ยนแปลงค่าพารามิเตอร์?

    **ตอบ** ต้องเรียก `esp_rmaker_param_update_and_report()` เพื่ออัปเดตค่าพารามิเตอร์ในหน่วยความจำและส่งยืนยันสถานะกลับไปยังคลาวด์ หากไม่รายงานผล สถานะบนแอปพลิเคชันจะไม่ตรงกับฮาร์ดแวร์จริง
   
3. เปรียบเทียบความแตกต่างระหว่างการพัฒนาอุปกรณ์ IoT ด้วย **Plain MQTT บน Mosquitto เอง (ในแล็บ 11.2)** กับการใช้ **ESP RainMaker SDK (ในแล็บ 11.4)** ในแง่ของความพยายามในการพัฒนา (Development Effort), ความปลอดภัย (Security), และการขยายระบบ (Scalability)

    **ตอบ** ตารางเปรียบเทียบ
   
| ด้านที่เปรียบเทียบ | Plain MQTT + Mosquitto (Lab 11.2) | ESP RainMaker (Lab 11.4) |
| :--- | :--- | :--- |
| **ความพยายามในการพัฒนา (Development Effort)** | ต้องออกแบบโครงสร้าง Topic, จัดการ Payload และพัฒนาแอปพลิเคชันควบคุมเองทั้งหมด | มีโครงสร้างข้อมูลมาตรฐาน แอปพลิเคชันสำเร็จรูป และสถาปัตยกรรมคลาวด์เตรียมไว้ให้พร้อมใช้งาน |
| **ความปลอดภัย (Security)** | ความปลอดภัยต่ำ เพราะส่งข้อมูลเป็นข้อความธรรมดา  | ปลอดภัยสูง บังคับใช้ mTLS และจัดการใบรับรองความปลอดภัยรายอุปกรณ์ (Per-Device Certificate) ให้อัตโนมัติ |
| **การขยายระบบ (Scalability)** | ขจำกัดตามทรัพยากรของเครื่องเซิร์ฟเวอร์หรือ Local Broker ที่ตั้งขึ้นเอง | ทำงานบนโครงสร้างพื้นฐาน AWS Serverless สามารถขยายรองรับอุปกรณ์จำนวนมหาศาลได้ทันที |
   
4. อธิบายขั้นตอนที่ทำให้ ESP RainMaker สามารถเชื่อมโยงการทำงานร่วมกับระบบสั่งงานด้วยเสียงของ **Google Home** หรือ **Amazon Alexa** ได้โดยไม่ต้องเขียนโค้ดเพิ่มเติมบนตัวบอร์ด ESP32

    **ตอบ** ใช้หลักการเชื่อมต่อแบบ Cloud-to-Cloud Integration โดยระบบเสียงจะส่งคำสั่งไปที่คลาวด์ของ RainMaker จากนั้นคลาวด์จะแปลงเป็นคำสั่ง MQTT มาตรฐานส่งไปที่ ESP32 ทำให้บอร์ดทำงานได้โดยไม่ต้องเขียนโค้ด API เพิ่มเติม
