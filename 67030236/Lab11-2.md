## 5. คำถามท้ายการทดลอง (Post-Lab Questions)
1. เพราะเหตุใดเราจึงต้องส่งข้อความสถานะ `iot/node01/status = "online"` ด้วยแฟล็ก `retain = 1` ควบคู่กับการตั้งค่า Last Will and Testament (LWT) ว่า `"offline"`
```text
เพื่อให้ Broker บันทึกสถานะ "online" เป็นค่าล่าสุดทับข้อความเดิมไว้เสมอ ทำให้ไคลเอนต์หรือแดชบอร์ดที่เพิ่งเชื่อมต่อเข้ามาใหม่สามารถทราบได้ทันทีว่าอุปกรณ์ออนไลน์อยู่ และเมื่ออุปกรณ์หลุดการเชื่อมต่อกะทันหัน Broker ก็จะส่งและแทนที่ด้วยข้อความ LWT "offline" ให้ทันทีโดยอัตโนมัติ
```
2. หากเครือข่าย Wi-Fi หลุดชั่วคราว คอมโพเนนต์ `esp-mqtt` มีพฤติกรรมการจัดการอย่างไร และเมื่อสัญญาณกลับมา โค้ดจำเป็นต้องเรียกฟังก์ชันเชื่อมต่อใหม่ด้วยตนเองหรือไม่
```text
คอมโพเนนต์ esp-mqtt มีระบบจัดการและพยายามเชื่อมต่อกลับไปยัง Broker ซ้ำให้อัตโนมัติ (Auto-reconnect) เมื่อสัญญาณ Wi-Fi กลับมาใช้งานได้ โดยโค้ดโปรแกรมไม่จำเป็นต้องสั่งฟังก์ชันเชื่อมต่อใหม่ด้วยตนเอง
```
3. ในฟังก์ชัน `telemetry_task` เพราะเหตุใดหลังจากเรียก `cJSON_PrintUnformatted(root)` แล้วเราจึงจำเป็นต้องเรียกฟังก์ชัน `free(json_str)` และ `cJSON_Delete(root)` เสมอ? หากละเลยจะมีผลเสียอย่างไรต่อหน่วยความจำของ ESP32
```text
เพราะทั้งสองฟังก์ชันมีการจองหน่วยความจำแบบไดนามิกบนฮีป (Heap) หากไม่สั่งคืนหน่วยความจำจะเกิดปัญหา Memory Leak สะสมจนแรมหมดและส่งผลให้ระบบแครช (Crash) หรือรีบูตตัวเองในที่สุด
```
